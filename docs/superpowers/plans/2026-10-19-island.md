# Fishboard Island Implementation Plan

Goal: Make a playable public Three.js island the home screen, with existing private Fishboard functions accessed through world objects.

Architecture: A client-only scene owns rendering and movement. Pure world rules handle boundaries, collisions and interaction range. A React HUD opens the existing authenticated Collection in an overlay with an initial tab/action.

Art: Original procedural low-poly meshes, seafoam ocean, layered sand shoreline, forest greens, coral roof, warm paper HUD. No external model assets.

Tasks:
1. Test movement boundaries, collision sliding, proximity and frame-time limits; implement world rules.
2. Build original scenery and character in Three.js; implement keyboard, click-to-walk, touch controls, cleanup and rendering fallback.
3. Connect five world stations to existing authenticated feature screens, preserving storage and generation behavior.
4. Verify types, existing tests, production build, and actual browser movement/interaction at desktop and mobile sizes.

Constraints: Never fake saved catches. Public island is explorable without account access. Stop movement while panels open. No generation requests during verification. Preserve existing APIs and account isolation.
