# Fishboard 全站 UI audit 與主頁 revamp

日期：2026-10-13（香港時間）

## 結論與本次範圍

網站最有辨識度的資產是個人的漁獲、像素水族箱與真實 Three.js 釣組。問題主要是呈現：原主頁把標題、三張統計卡、水族箱、最近漁獲及列表堆在相近的視覺層級；資訊齊全，但缺少專業的節奏、主視覺與故事感。

本次完成登入後主頁的視覺與互動重設，保留實際紀錄操作。其餘頁面完成 audit，列出後續建議，沒有把整站操作流程一併重寫。訪客登入頁、圖鑑、詳情、地圖、設定、裝備儲存及登入邊界繼續沿用現有功能。

依據：目前路由及元件源碼、樣式、測試；另在隱藏的本機瀏覽器以正式 UI 元件及 repo 外的示範資料檢查主頁、圖鑑、魚種詳情、漁獲詳情、設定與地圖。這不是登入真實帳戶的驗收，也不是實體手機、正式部署或 Lighthouse 量測。當前工具沒有提供 codebase graph，因此本次使用源碼證據，不宣稱 graph coverage。

## 跨頁問題

### P2：小字與列表資訊損失

原樣式在多處使用 9–11px 的資料文字，手機尤為明顯。主頁已放大列表主字、日期及地點；相同 `CatchRows` 在圖鑑詳情及地圖仍沿用舊規格。這是下一輪最值得統一的實用改動。

主頁水族箱暫停、跑馬燈暫停與清除篩選已調整為 44px。其他細小文字入口應逐一按實際點擊範圍檢查，而非只看圖示大小。

游魚選取會顯示魚種、次數及尺寸，但 tooltip 目前沒有直接前往魚種詳情的入口。主頁保留「探索圖鑑」；後續可在 tooltip 加入清楚的詳情連結，讓收藏互動有完整的下一步。

### P2：樣式重複與字體來源

`globals.css`、`fishlog.css` 與 `fishboard-ui.css` 含多個歷史版面及覆蓋規則；部分舊版 `app/collection.tsx`、`app/aquarium.tsx` 仍在 repo，但不等於目前 `/collection` 路由。維護時要先跟路由追到實際元件，避免修改錯版本。

主頁使用本機 Geist 字體，中文使用系統繁中字體。原 `fishlog.css` 仍有 Google Fonts 的 Inter／IBM Plex Mono 載入；本次不把該舊字體套進新版主頁。後續可確認其他頁面需求後，移除多餘字體及未使用樣式。

### P2：3D 套件兼容提示

背景檢查設定頁時，Three.js 提示 `PCFSoftShadowMap` 已移除，回退為 `PCFShadowMap`。真實模型 canvas 與五個裝備槽仍載入。本次未改動 3D 來源；下一輪可整理陰影設定，避免升級套件後留下兼容提示。

### P3：一致的圖片後備與錯誤回復

新版主頁故事圖片載入失敗會回到對應像素魚，保留紀錄連結。原相詳情、地圖載入與其他外部資源可在後續採用一致的後備與重試語言。沒有將外部照片混入私人漁獲，亦沒有虛構評語、天氣或合作品牌。

## 主頁設計規格

採用使用者指定的 `gpt-taste`。以提示的字元數 38 作 deterministic seed，選擇結果：

- Hero：Editorial Split，寬幅兩行標題，右側海岸照片。
- 字體：Geist；中文由 PingFang TC／Microsoft JhengHei 補足。
- 組件：標題內嵌微型照片、真實魚種文字 marquee、真實漁獲故事 carousel（重疊像素魚收藏圖像代替虛構人物評語）。
- GSAP：桌面固定左側故事標題、圖片隨捲動縮放並淡出。

色彩仍以白、淡藍、海洋藍為主；深色使用既有主題。海岸使用現有已授權的本機照片 `public/fish/landing-coast.webp`，來源見相同目錄的 `.txt` credit。曾檢查 picsum 的 seeded 參考圖片，但內容為山景；最終沿用與釣魚情境相關的海岸照片，不將隨機照片偽裝成用戶漁獲。

### 結構與數學檢查

1. Navigation：沿用桌面側欄與手機左右分離式 dock。
2. Attention：兩行 H1，`max-w-6xl`，沒有徽章、統計或標籤堆積；兩個操作為新增及跳到紀錄。
3. Interest：水族箱＋兩個摘要卡，下方真實魚種跑馬燈與紀錄工具列。
4. Desire：真實紀錄的照片／像素魚、魚名、地點、日期、備註及手動切換。
5. Action：深藍新增漁獲區塊及簡潔頁尾。

桌面 bento 為三欄兩列共六格：水族箱佔兩欄兩列＝四格，兩張摘要各佔一格，總數六格。手機為兩欄，水族箱佔第一列兩格，兩張摘要填第二列。兩種布局都使用 `grid-auto-flow: dense`，沒有空格。不是六張小卡，實際只有三個主要面板。

大段間距桌面約 96–128px，手機約 68–80px；紀錄入口在 hero 可直接跳轉，不要求用戶捲完整個頁面才找到搜尋。手機列表保留日期、地點、長度，英文魚名可省略顯示空間，但不刪除原值。

### 動態與可存取性

- GSAP 限定在新 `Home` 元件；圖鑑及詳情不再從共用 `pages.tsx` 匯入主頁動畫依賴。
- 1101px 以上、未要求減少動態時，左側故事標題固定，右側內容正常捲動；結束位置由內容高度計算。
- 圖片從 0.8 放大到 1，離開視窗再淡至 0.2；使用 ScrollTrigger scrub，hover 是內層圖片，避免與捲動 transform 爭用。
- `useGSAP` 與 `gsap.matchMedia` 在卸載、資料重新載入或 breakpoint 改變時清理動畫與 pin。
- 手機取消 pin；`prefers-reduced-motion` 取消捲動動畫、marquee 與過渡，保留全部內容。
- Marquee 有 44px 暫停按鈕、hover／focus 暫停、對螢幕閱讀器只讀一次魚種清單；沒有自動輪播漁獲。
- 故事最多五筆，按實際漁獲日期排序；只顯示有對應魚種的紀錄。刪除目前故事後回到仍存在的第一筆。
- 日期、尺寸與空資料使用實際值或破折號；讀取時明示讀取，沒有虛構零值。
- 原相使用 `next/image` 的 `unoptimized`，讓瀏覽器直接帶登入 session 讀取私人圖片；品牌海岸使用正常圖片最佳化。
- 故事備註顯示四行，完整內容在漁獲詳情。固定文字區高度避免切換故事令 pin 結束位置跳動。
- 沒有背景 WebGL 水波；像素水族箱游魚及設定頁真實 Three.js 模型保留。

實作依循 [GSAP React lifecycle](https://gsap.com/resources/React/) 與 [ScrollTrigger 文件](https://gsap.com/docs/v3/Plugins/ScrollTrigger/)。

## 驗證與後續接受範圍

主頁新增四項互動測試：空日誌新增／關閉、故事切換／回環／刪除後恢復、讀取狀態、私人圖片失敗後備。既有資料、API 安全、地點 touch 操作、地圖 marker、游魚、裝備及手機導覽測試仍需通過。

背景布局檢查包括 1440px、390px、320px 與中等桌面寬度；觀察兩行標題、無文件橫向溢出、三面板填滿、手機地點可見、深淺色按鈕文字、搜尋／清除／故事切換及切換路由後 pin 清理。正式驗證結果由本次提交時的測試及建置輸出確認，不以示範資料宣稱 Firebase／私人原相的線上服務已驗收。

後續優先順序：統一其他頁面的列表與小字 → 設定配件閱讀體驗 → 品牌字體與樣式去重 → 空狀態／地圖重試。保留原有桌面導覽、手機 add 向左收起、map marker 篩選與設定內 loadout 的決定。

本次最終檢查：84 項測試通過；TypeScript 檢查及 Vercel 使用的 Next.js production build 成功；lint 零錯誤，保留原有 12 項警告。1440px、960px、390px、320px 的主頁標題均為兩行，文件沒有橫向溢出；960px 及手機沒有 pin，1440px 有實際 ScrollTrigger pin 與圖片動畫，離開主頁清理 pin。
