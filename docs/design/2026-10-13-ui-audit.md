# Fishboard 全站 UI audit 與主頁 revamp

日期：2026-10-13（香港時間）

## 結論與本次範圍

網站最有辨識度的資產是個人的漁獲、像素水族箱與真實 Three.js 釣組。問題主要是呈現：原主頁把標題、三張統計卡、水族箱、最近漁獲及列表堆在相近的視覺層級；資訊齊全，但缺少專業的節奏、主視覺與故事感。

本次完成登入後主頁的視覺與互動重設，保留實際紀錄操作。其餘頁面完成 audit，列出後續建議，沒有把整站操作流程一併重寫。訪客登入頁、圖鑑、詳情、地圖、設定、裝備儲存及登入邊界繼續沿用現有功能。

依據：目前路由及元件源碼、樣式、測試；另在隱藏的本機瀏覽器以正式 UI 元件及 repo 外的示範資料檢查主頁、圖鑑、魚種詳情、漁獲詳情、設定與地圖。這不是登入真實帳戶的驗收，也不是實體手機、正式部署或 Lighthouse 量測。當前工具沒有提供 codebase graph，因此本次使用源碼證據，不宣稱 graph coverage。

## 跨頁問題

### P2：小字與列表資訊損失

原樣式在多處使用 9–11px 的資料文字，手機尤為明顯。主頁已放大列表主字、日期及地點；相同 `CatchRows` 在圖鑑詳情及地圖仍沿用舊規格。這是下一輪最值得統一的實用改動。

主頁水族箱暫停、跑馬燈暫停與清除篩選已調整為 44px。其他細小文字入口應逐一按實際點擊範圍檢查，而非只看圖示大小。

游魚選取會顯示魚種、次數及尺寸，但 tooltip 目前沒有直接前往魚種詳情的入口。主頁保留「探索圖鑑」；後續可在 tooltip 加入清楚的詳情連結，讓收藏互動有完整的下一步。

### P2：樣式重複與字體來源

`globals.css`、`fishlog.css` 與 `fishboard-ui.css` 含多個歷史版面及覆蓋規則；部分舊版 `app/collection.tsx`、`app/aquarium.tsx` 仍在 repo，但不等於目前 `/collection` 路由。維護時要先跟路由追到實際元件，避免修改錯版本。

主頁使用本機 Geist 字體，中文使用系統繁中字體。原 `fishlog.css` 仍有 Google Fonts 的 Inter／IBM Plex Mono 載入；本次不把該舊字體套進新版主頁。後續可確認其他頁面需求後，移除多餘字體及未使用樣式。

### P2：3D 套件兼容提示

背景檢查設定頁時，Three.js 提示 `PCFSoftShadowMap` 已移除，回退為 `PCFShadowMap`。真實模型 canvas 與五個裝備槽仍載入。本次未改動 3D 來源；下一輪可整理陰影設定，避免升級套件後留下兼容提示。

### P3：一致的圖片後備與錯誤回復

目前主頁只保留品牌海岸圖片；私人原相在漁獲詳情查看。原相詳情、地圖載入與其他外部資源可在後續採用一致的後備與重試語言。沒有將外部照片混入私人漁獲，亦沒有虛構評語、天氣或合作品牌。

## 主頁最終規格（同日精簡）

初次 revamp 使用指定的 `gpt-taste`，以字元數 38 作 seed：Editorial Split、Geist、標題內嵌圖片、魚種 marquee、漁獲 carousel、GSAP pin 及 scale／fade。其後使用者明確要求主頁到 catch logs list 即止，新增只保留 navbar；以下最終規格取代初版的故事、pin 與底部 CTA。

### 內容順序

1. 沿用桌面側欄、頂部操作與手機分離式 dock。
2. 海岸主視覺、寬幅兩行 H1 與「瀏覽紀錄」跳轉；hero 不放新增漁獲按鈕。
3. 像素水族箱＋漁獲／魚種摘要＋最長紀錄。
4. 真實已收藏魚種 marquee，可暫停。
5. 搜尋、魚種／地點／年份篩選與 catch logs list，主頁在這裏結束。

不再渲染故事 carousel、底部新增 CTA 或頁尾；相關 CSS、狀態、圖片後備元件與 pin 程式亦一併刪除。新增只由 `Shell` 的桌面頂部或手機左下按鈕開啟原有 modal；`/add` 直接入口保留。

### 排版與動態

保留白、淡藍、海洋藍及深色主題；本機 Geist 配中文系統後備。Hero 採 `max-w-6xl` 與固定兩行文案，保留現有已授權海岸照片，來源為 `public/fish/landing-coast-credit.txt`。不將隨機照片當作私人漁獲。

桌面 bento 三欄兩列共六格：水族箱佔四格，兩張摘要各佔一格，沒有空格；手機轉兩欄，水族箱佔第一列，兩張摘要填第二列。實際為三個主要面板，使用 `grid-auto-flow: dense`。

海岸仍使用 GSAP ScrollTrigger scale／fade；`useGSAP` 與 matchMedia 在卸載或動態偏好改變時清理。沒有 pin、故事動畫或背景 WebGL 水波。減少動態設定取消捲動動畫、marquee 與過渡。水族箱游魚與 Three.js 裝備不受這次精簡影響。

手機列表保留魚種、日期、地點及尺寸；水族箱暫停、marquee 暫停與清除篩選操作為 44px。讀取與空資料狀態保留，不使用虛構零值。

實作參考 [GSAP React lifecycle](https://gsap.com/resources/React/) 與 [ScrollTrigger 文件](https://gsap.com/docs/v3/Plugins/ScrollTrigger/)。

## 驗證與後續範圍

主頁四項測試改為：列表是最後內容且沒有額外新增入口、空日誌保留跳轉與空狀態、搜尋與年份組合篩選／清除、讀取狀態不展示虛構零值。已移除與取消功能相關的故事輪播及圖片失敗測試。

桌面及手機背景檢查確認列表為主頁終點；桌面有一個導覽新增入口，手機有獨立左下新增，向下捲動會收起。新版截圖及資料來源說明見 `docs/screenshots/README.md`，README 直接引用目前畫面。

截圖使用目前元件及 repo 外的示範帳戶適配器，不含私人紀錄或產品登入繞過。這次不重新宣稱 Firebase／Cloudinary／Workers AI 的線上服務或實體手機已驗收。

精簡版最終檢查：84 項測試通過，Next.js 正式建置及內含的 TypeScript 檢查成功；lint 零錯誤，保留原有 12 項警告。README 的 11 個本機文件／圖片連結均存在，四張 JPEG 已逐張檢查。

後續優先順序仍為：統一其他頁面的列表與小字 → 設定配件閱讀體驗 → 品牌字體與樣式去重 → 空狀態／地圖重試。保留手機 add 向左收起、marker 篩選與設定內 loadout 的決定。
